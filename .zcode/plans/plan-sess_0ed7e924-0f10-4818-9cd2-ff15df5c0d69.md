# wechaty-bot × Agent-Reach / Scrapling / patchright 集成方案

## 研究结论（三者配合模式）

三者是**分层互补**关系，不是并列工具：

- **Agent-Reach**（本机已装好，doctor 9/16 渠道可用）= 平台接入路由器：搜索走 Exa（mcporter 免 key）、网页阅读走 Jina Reader、视频走 yt-dlp、GitHub 走 gh、V2EX/RSS 走公开 API。它本身是 CLI 工具箱，bot 按《agent-reach skill 路由表》（`C:\Users\wwb\.agents\skills\agent-reach\SKILL.md` + references/）直接调用上游 CLI。
- **Scrapling**（Python 3.13 已就绪）= 通用抓取框架：用其 `Fetcher`（TLS 指纹伪装 HTTP，无需浏览器）+ 自适应正文提取 + `page.markdown()`，做本地正文提取层（URL 不出本机）。
- **patchright** = Playwright 免检测补丁版，有 **Node 原生包**：SPA/强反爬页面的无头渲染兜底，懒加载可选依赖。

**数据流**：微信消息 → 意图识别（搜索词/链接/视频链接）→ 分层降级抓取 → Markdown/摘要 → 现有 `chat({systemExtra})` 通道喂人设 AI → 多气泡回复。

## 分层降级链（链接处理核心改造）

```
L0 平台特化路由（按域名硬编码白名单，先过 validateExternalUrl）
   ├─ bilibili.com / b23.tv / youtube / douyin → yt-dlp 拿标题+up主+描述+字幕
   ├─ v2ex.com → 公开 API JSON
   ├─ github.com → gh api（README/描述）
   └─ mp.weixin.qq.com → Jina Reader（公众号正文）
L1 现有 fetchPageText（原生 fetch，保留不动，最快）
L2 Scrapling：spawn python scripts/reach_scrape.py <url>（未装则跳过）
L3 Jina Reader（r.jina.ai，外部服务，config 可关，隐私提示写入配置注释）
L4 patchright 无头渲染（懒加载，未安装则跳过并 log 提示解锁命令）
每层失败原因+耗时记 log，全部失败回退现有"打不开"话术。
```

## 功能实现（用户已选定三项）

### 1. 链接点评增强 — 改造 `src/handlers/on-link.js`
- 抓取调用从 `fetchPageText(url)` 换成新模块 `fetchRich(url)`（上面降级链），返回 `{ok, kind, source, summary}`。
- B站/YouTube 命中字幕时，prompt 从"点评链接"升级为"总结这个视频讲了什么"（kind: 'video'）。
- 限流/准入/多气泡发送逻辑全部不动。

### 2. 聊天搜索命令 — 新增 `src/handlers/search.js`
- 触发词（config 可配）："搜一下 XX" / "帮我搜 XX" / "搜索 XX"，消息以触发词开头且 query 非空。
- 放在 `src/handlers/on-message.js` 链接分支**之前**（防含 URL 搜索词被链接分支截走）；群聊需满足现有 mention/唤醒词判定。
- 后端：spawn `mcporter call 'exa.web_search_exa(...)'`（零 key，已验证可用），解析 top5 标题+URL+摘要 → `chat({key: 'search-once:<ts>', systemExtra})` 人设汇总播报。
- 限流：复用 `checkRate/recordReply`，key `search:room:<id>`/`search:private:<id>`，默认 60s 冷却 + 每日 20 次（计每日上限）。

### 3. 视频字幕总结 — 在 `src/reach/platforms.js` 实现
- 域名命中视频平台 → spawn `yt-dlp -J <url>`（元数据）+ `--write-auto-sub` 拿中文字幕到系统临时目录（读取后立即清理），字幕截断后与元数据一起给 AI 总结。
- 字幕拿不到（如抖音）自动降级为"标题+描述"点评。

## 安全约定（延续项目既有底线）

1. 所有 URL（含传给子进程的）先过现有 `validateExternalUrl`（SSRF 防护不动）。
2. L0 平台路由是**硬编码域名白名单**，不接受聊天内容注入任意目标。
3. Jina/Exa 为外部服务，URL/query 会发往第三方——config 注释明示，`reach.jina.enabled` 可关；baseUrl 类敏感项不从聊天内容来。
4. patchright 渲染层无 SSRF 二次校验（浏览器自行解析 DNS），在代码注释标注此残余风险与 L1 一致的缓解边界。
5. 子进程超时强杀 + 输出截断，防挂起拖垮 bot；临时字幕文件即用即删。
