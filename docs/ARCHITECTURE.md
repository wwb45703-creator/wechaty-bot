# 当前架构（2026-10-30）

## 运行边界

Windows 微信 3.9.10.27 与 puppet-xp/Frida、便携 Node 18 保持原约束。Wechaty 负责收发，Ollama 负责本地生成；没有引入第二个 Agent 内核。控制台为 Electron 独立进程，不持有微信发送权。

## 消息与模型

`handlers/on-message.js` 先按账号与稳定会话 ID 统一准入，再分流文本、搜索、链接、图片与表情。处理器生成待发内容，`messaging.js` 独占排队、去重、额度预留和发送；欢迎与 cron 也走同一出口。

`ai.js` 保留会话串行生成、思考标记清理与有限复读重试。`context.js` 为文本、视觉、定时和控制台诊断统一构造角色上下文。只有发送确认的文本才进入助手历史；控制台诊断不执行技能或保存成长。`model-provider.js` 只提供环回 Ollama 适配，拒绝模型重定向，保留返回用量的统一接口。

ScopeRef 包含 platform、accountId、conversationId、personaId、subjectId。群名、昵称只是展示属性；多人群聊按角色共享当前群上下文，私人事实、关系与经历仍按用户隔离。

## 社交事件与恢复

`social/index.js` 的 `state/social/journal.json` 是权威记录，快照带处理版本并可重建。发送确认后提交唯一互动，事实提取和共同经历补充同一事件，不重复加分。角色汇总的兴趣只包含有限分类；私人原文不会进入跨群人格摘要。

`outbox-store.js` 为机器人与控制台提供共享锁、原子写和字段差量合并。已确认发送与社交提交之间的 checkpoint 只保留必要范围、事件 ID、代际和分类，不留原文或回复。恢复只补事件，不重发；未知发送保留保守去重。额度恢复释放无主预留，已引用的未知发送不会被误释放。

遗忘先持久化删除代际与主体标记，再删除来源事件和派生数据。失败的遗留文件/候选清理保留可重试意图；首次迁移也尊重主体删除标记。另一个进程遗忘后，机器人每次读取内存历史都会核对持久代际。控制台立即清除发件箱归因，旧缓存保存不会将其恢复。

旧 `memory.js` 和部分 personality 导出保留兼容入口，在线路径以 scoped journal 为准。原始 legacy 文件通过首次登录迁移处理，不能通过直接删一份旧文件代替完整遗忘。

## 工具与控制台

`skills/review-store.js` 管理候选、内容哈希、独立离线评测、人工启用、停用及回滚。`tracer.js` 仅持久化分类与散列来源，不存聊天原文；SOP/DSL 候选采用受限模板，不自改源码。`dsl-executor.js` 有动作白名单、小正则方言、步数和截止时间。

`external-http.js` 统一检查 DNS 并固定连接 IP、逐跳重定向、限量读取正文，超时涵盖 DNS 和正文。独立网络栈的自动后端暂时隔离。云端推理未开启，隐式搜索默认关闭。

控制台只接受自身主 frame 的白名单 IPC。社交查看和遗忘要求完整 scope。发布包同时携带只含源码的 bot-runtime；隔离 smoke 强制临时配置、禁用真实控制、隐藏离屏渲染，并验证包内模块 fallback。

详细操作与验收边界见 SOCIAL_GROWTH.md、TESTING.md、QA_REPORT.md。
