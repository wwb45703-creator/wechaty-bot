# 控制台改造与模块验收计划

## 范围与实现原则

真实项目位于 `D:\wechaty-bot`；`E:\wechaty-bot` 是迁移后残留目录。保留 Electron + 原生 HTML/CSS/JavaScript、隔离 preload 和现有业务服务。保持 Node 18、微信 3.9.10.27、现有 PID/VBS 启停机制，不改用户 `config.json`、停用标记或真实聊天资料。

视觉使用中性灰白与石墨、克制绿色、清晰表格和紧凑层级；移除粉色渐变、毛玻璃、背景光斑和导航 emoji。提供浅深色、键盘焦点、窄屏滚动、加载/空/失败状态。功能文案据实际数据与能力呈现。

## 审查发现与顺序

1. 优先修复插件和知识库桥接：旧接口会把服务错误当成空列表，安装与启停成功条件不严，知识库缺少创建/导入/选库入口。
2. 完成各页功能闭环：人格、关系、记忆三个导航原先都重定向到社交成长；应使用完整 scope 的权威日志重新提供独立视图。
3. 全界面应用一致视觉与状态，去除重复/夸张能力描述。
4. 离线门禁、隔离 Electron 页面与打包检查通过后，交付明确的验证记录；真实微信/模型/第三方服务和模拟测试分开记录。

## 删除与隔离验收

- 任意详情仅通过 `listSocialScopes → getSocialScope(scope)`，scope 五字段均为非空字符串；拒绝裸用户 ID、文件名或昵称当查询键。
- 人格、关系、记忆视图的遗忘统一调用 `forgetSocialSubject({scope,allConversations,confirmed:true})`，不是文件 unlink。
- 用户先选择范围，再打开遗忘面板并勾选确认；扩大到全部会话后重新确认。确认面板明确会清除所选范围全部角色；不误称仅删除一条事实。
- 切换选择、并发刷新时，过期请求不覆盖最新选择；同一删除操作不可重复提交；失败保留错误并允许重试。
- 保持当前 IPC 来源限制、contextIsolation、sandbox 与离线 smoke 阻断；不得为了截图连接生产服务或执行真实遗忘。

## 权威接口与测试

- 桥接以本机已安装 AstrBot 的 `dashboard/api/plugins.py`、`knowledge_bases.py` 和 `dashboard/schemas.py` 为当前接口依据；插件/知识库 API 分别要求 `plugin`/`kb` 权限。
- `node scripts/verify-all.mjs` 为项目必须通过的离线回归门禁。它不证明真实微信收发、真实模型推理、插件联网安装或向量召回已经成功。
- Electron 隔离 smoke 应至少覆盖主页、插件、知识库、人格、关系、记忆、技能审核、社交成长，并检查按钮/字段/空与错误状态；使用临时数据根，不读取真实私人资料。
- `scripts/test-scoped-views.cjs` 使用全新隐藏 Electron 和仅含合成资料的 API fixture，专项验证完整范围、请求竞争、删除确认/范围扩大/部分失败重试、HTML 转义、来源、搜索和空态。用 `ui/node_modules/electron/dist/electron.exe scripts/test-scoped-views.cjs` 执行并等待进程结束；PowerShell 下使用 `Start-Process -WindowStyle Hidden -Wait -PassThru` 检查退出码。
- 打包前只关闭路径位于 `ui/release/win-unpacked` 的控制台，保留机器人与无关 node；产物核对版本和运行路径，禁止用旧包截图代替源码验收。
