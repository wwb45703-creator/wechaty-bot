# 社交成长与技能审核

本轮保留 Node 18、Wechaty/puppet-xp 和现有微信版本。日常推理只使用本机 Ollama，没有开启云端模型，也没有接入 Hermes 服务。

## 消息与角色

- 所有文本、链接、搜索、图片点评、表情回应、欢迎和定时消息共用准入、会话队列、额度预留与发送出口。未登记或已禁用的群不会处理消息。
- 会话使用平台、机器人账号、群 ID/私聊 ID，角色另有独立上下文。昵称和群名只是展示信息。同名群不会合并，群改名不会丢上下文。
- 角色切换保留各角色的历史和成长。当前角色由现有角色卡配置确定；修改角色名称相当于建立新的角色身份，应先保留原名再迁移。
- 发送接口确认后才增加关系和人格贡献。气泡部分成功只计算一次；发送结果不明的消息不会自动重发，以免重复发送。这里的确认不等于对方已读。

## 记忆、成长与遗忘

社交数据的权威记录位于 `state/social/journal.json`，`snapshot.json` 是可以重建的派生视图。写入使用原子替换和单写锁；同一互动重复处理不会重复加分。

事实、共同经历、情绪和成员关系按账号、会话、角色、用户隔离。角色可以跨会话累积抽象兴趣，但不会把私人具体事实传播到别的群。一次争执不会直接变成永久性格；单人每天的贡献有持久化上限。

- `我的记忆`：查看当前角色在本会话保存的本人信息。
- `忘记我`：删除当前会话所有角色中关于本人的事实、经历、关系、偏好、候选来源及可归因成长贡献。
- `忘记我全部会话`：删除当前机器人账号所有会话中关于本人的记录。
- 控制台的“社交成长”页提供明确范围的查看和遗忘操作。

遗忘会先持久化删除代际，再取消旧工作。推理和记忆提取即使稍后结束，也不能重新写回；同群已读取旧上下文的任务也会失效。

首次登录取得真实机器人账号 ID 后，程序迁移旧数据。迁移冻结当时的角色映射，保存备份和清单，重复执行不会再次分配角色。无法确定所属群的旧全局关系标为 legacy，不自动复制到各群。旧默认人格只归入实际默认角色。原始日志和用户自行复制到项目外的备份不会被承诺为可精确删除的数据；恢复外部备份前须应用最新遗忘清单。

## 技能审核

技能按以下顺序生效：纠错或工具失败分类 → 候选 → 独立离线评测 → 人工确认内容哈希 → 启用。普通聊天和候选元数据都不能自行授予启用权限。

控制台“技能审核”页可以查看来源、前后差异、评测、拒绝、启用及回滚。所有运行版本存放在 `state/skills/`，不会自动修改源码。

目前自动候选使用保守的确定性模板，覆盖简短/单条表达纠正和公开文档读取失败。它不是模型权重训练，也不声称能自动发明任意技能。SOP 静态验收不代表真实模型的自然度已经改善；实际对话效果仍需本地模型回放比较。

DSL 只允许页面读取、受限正则提取、文本模板和搜索；不允许 shell、eval 或任意代码。流水线有步数、输入长度、超时与取消限制。评测使用审核器自带的独立样本和模拟网络，候选不能提交自己的“通过”结果。已有仓库样例也必须经过审核才能启用。

## 联网与可选后端

本地推理不等于完全不联网。显式搜索词和公开链接仍会发送给目标网站；普通社交聊天默认不做隐式搜索，私人记忆不作为工具输入自动外发。

原生 HTTP 和内置公开平台 API 共用 DNS 校验与 IP 固定、逐跳重定向校验、400KB 正文限额，以及涵盖 DNS/正文的完整截止时间。SSRF 拒绝是终态，不再换后端重试。

Scrapling、浏览器和 Agent Reach CLI 的自动抓取入口暂时隔离，因为这些独立网络栈尚不能遵守同一出口约束。B站、V2EX、GitHub 的内置公开 API 以及普通网页读取保留。Jina 仍需配置显式开启；它会将目标链接交给第三方读取。

## 验收、迁移与发布

使用项目便携 Node：

```powershell
D:\wechaty-bot\runtime\node18\node.exe scripts/verify-all.mjs
```

默认门禁使用临时数据、合成配置、模拟模型和网络，不启动微信、Ollama或插件服务，不修改日常配置。覆盖映射见 `TESTING.md`。真实微信/Frida 收发和模型语言质量不计作离线门禁的已验证内容。

上线前保留项目 Git 提交以及 `config.json`、`state/`、`memories/` 的本机备份，不把私人数据提交到 Git。通过三件套重启时首次迁移才会运行；开发测试不会替用户启动服务或清除停用开关。需要回退程序时保留新日志和删除代际，不可直接恢复一份已包含被遗忘数据的旧备份。

当前 JSON 事件存储适合单机、小规模群聊。历史增长时读写和重放成本线性上升；本轮没有引入数据库，也不承诺无限历史容量。
